# 足球球员生涯模拟器 MVP 设计规格

日期：2026-08-27  
状态：已获用户口头批准，等待书面规格复核

## 1. 目标

使用 Next.js 与 TypeScript 构建一个原创的浏览器足球球员生涯模拟器。产品复现公开可观察的品类机制，但不复制 Il Nuovo Goat 或其他产品的源码、文案、球队数据库、品牌、商标、美术或视觉设计。

玩家从 16 岁开始一名虚构球员的职业生涯，通过训练、比赛、关键时刻、事件、合同和转会选择推进到 36 岁退役，并获得可以解释的 GOAT Score。

MVP 的成功标准：

1. 经典模式与详细模式均可完成一段 16–36 岁的完整生涯。
2. 内置原创世界能够稳定完成联赛、杯赛、升降级、洲际赛事和国家队结算。
3. 三个本地存档槽支持自动保存、刷新恢复及 JSON 导入导出。
4. 玩家可以导入符合规范的原创球队世界数据库；无效文件不能改变现有数据。
5. 相同规则版本、seed 和玩家指令序列必须产生相同结果。

## 2. 技术与架构

采用 Next.js App Router 与 TypeScript。游戏规则实现为不依赖 Next.js、React、浏览器或存储层的纯 TypeScript 模块；Next.js 仅负责页面、交互和应用装配。

```text
src/
├── app/                    Next.js 页面与最小交互界面
├── game/
│   ├── domain/             球员、球队、联赛、比赛、生涯等类型
│   ├── engine/             随机数、比赛、赛季、成长、伤病、转会
│   ├── events/             原创职业事件与触发条件
│   ├── scoring/            分位置的 GOAT 评分
│   ├── world/              默认虚构世界生成与赛程
│   └── application/        开始生涯、推进比赛、选择事件等用例
├── persistence/            IndexedDB 三档存档、JSON 导入导出
├── import/                 玩家世界数据库格式、校验与错误报告
└── components/             无品牌视觉的表单、表格和操作控件
```

### 2.1 引擎接口原则

- 引擎接收当前不可变状态、玩家指令和确定性随机数状态，返回新状态、领域事件和结构化错误。
- 引擎不能读取 DOM、React 状态、IndexedDB、系统时间或未经注入的随机数。
- 所有 ID、赛季日期和随机行为均来自稳定规则或 seed。
- 规则版本写入存档，为未来迁移保留接口。
- 经典与详细模式必须共用球队实力、赛程、比赛解析、成长、伤病、转会和评分规则。

### 2.2 客户端与持久化

- 游戏运行在浏览器中，不使用账号、数据库、Server Actions 或外部 API。
- IndexedDB 保存三个生涯槽及一个当前世界配置，避免详细比赛历史超出 `localStorage` 容量。
- JSON 文件提供生涯存档和世界数据库的手动迁移。
- 首版可按普通 Next.js Node 应用部署；代码不得依赖专有部署服务。

## 3. 世界模型

默认世界由 4 个虚构国家组成。每国有 2 级联赛，每级 10 队，共 80 队。

每个国家包含：

- 两级双循环联赛，每队每季 18 场。
- 由本国 20 队参加的全国杯赛。
- 一级联赛后两名降级，二级联赛前两名升级。
- 由各国一级联赛高排名球队参加的洲际杯。
- 根据国籍、位置、能力、状态和出场情况征召的虚构国家队。

球队保存以下模拟字段：

- 稳定 ID、名称、国家和当前级别。
- 声望、财政、青训和训练设施。
- 门将、后卫、中场、前锋四条阵线实力。
- 战术风格标签和主场修正。

MVP 不建立完整 NPC 球员数据库。球队表现由阵线实力、状态、战术标签及少量按需生成的具名关键球员共同决定。

## 4. 球员与生涯模型

### 4.1 玩家球员

球员身份包括姓名、国籍、位置家族、惯用脚和号码。位置家族限定为门将、后卫、中场、前锋四类。

球员能力包括技术、意识、身体、心理四个主属性，以及由主属性和位置权重计算的派生能力与 OVR。

动态状态包括潜力、体能、状态、士气、教练信任、声望、身价、合同、球队角色、国家队状态和伤病。

生涯档案逐季记录：

- 出场、首发、分钟、进球、助攻、零封、扑救和平均评分。
- 联赛、国内杯、洲际赛事及国家队数据。
- 球队奖杯、个人奖项、转会、租借、合同和里程碑。

### 4.2 存档状态

每个存档包含：

- 世界 seed、规则版本和确定性随机数游标。
- 当前世界、赛季、赛程、积分榜及杯赛状态。
- 球员完整状态、模式及尚未处理的事件或关键时刻。
- 玩家指令历史、逐季档案、转会、奖杯、奖项和国家队记录。
- 最近一次成功操作前的恢复快照。

## 5. 世界数据库导入

世界数据库使用带 `schemaVersion` 的 JSON Schema。文件必须恰好定义 4 个国家，每国 2 个级别，每级 10 支球队。

校验要求：

- 国家、联赛和球队 ID 在各自作用域内唯一且稳定。
- 名称非空；禁止控制字符和超出合理长度的内容。
- 声望、财政、设施和阵线实力处于规定数值范围。
- 每支球队只属于一个国家和一个级别。
- 升降级、杯赛和洲际资格能够从结构中无歧义地产生。

导入流程必须先解析、校验和生成预览，再要求用户确认替换当前世界。任何错误均返回字段路径、错误类型和可修复说明；失败导入不得覆盖当前世界或任何存档。

## 6. 游戏模式

模式只允许在赛季开始前切换。进行中的赛季不能切换模式。

### 6.1 经典模式

每个赛季流程：

1. 玩家选择技术、意识、身体或心理训练重点。
2. 玩家选择争取主力、稳健发展、追逐荣誉或寻求转会的职业倾向。
3. 引擎通过共用比赛模型分段批量解析联赛、国内杯和洲际赛事；每段结束于下一个事件检查点。
4. 赛季中暂停 4–6 次，处理符合条件的训练、伤病、关系、媒体、国家队或生活事件。
5. 展示球队排名、杯赛路径、个人数据、能力变化和重要新闻。
6. 处理续约、报价、主动求购或留队。
7. 结算升降级、奖项、国家队赛事、年龄和下一赛季。

性能和节奏目标：普通桌面浏览器单赛季结算低于 1 秒；完整生涯约 20–40 分钟。

### 6.2 详细模式

详细模式使用同一份赛程，但逐场推进：

1. 展示对手、赛事、球员状态和预计角色。
2. 引擎推进比赛；球员上场时生成 0–3 个关键时刻。
3. 玩家选择行动，结果立即写入比分、个人表现和状态。
4. 比赛结束后展示文字时间线、评分、数据、伤病和积分变化。
5. 每完成 4 场俱乐部赛事执行一次事件检查；赛季中段和赛季结束另有固定检查点。
6. 赛季结束后进入与经典模式相同的合同和结算流程。

详细模式完整生涯目标为 3–5 小时，必须支持自动保存和分多次完成。

### 6.3 关键时刻

关键时刻按位置生成：

- 前锋：直接射门、调整后射门、横传、制造犯规。
- 中场：直塞、控球降速、远射、战术犯规。
- 后卫：上抢、封堵路线、保持站位、参与定位球。
- 门将：出击、守门线、快速发动反击、拖延节奏。

选项只展示风险类别，不显示精确成功率。结果由相关能力、体能、状态、士气、比赛局势、对手实力、选择风险和 seed 决定。失败可以影响比分、评分、信任、体能、伤病或停赛。

## 7. 成长、伤病与生涯曲线

- 16–21 岁：成长最快，出场时间、训练重点、潜力和设施影响最大。
- 22–28 岁：巅峰发展期，稳定高水平表现仍可带来成长。
- 29–32 岁：能力趋稳，身体属性缓慢下降。
- 33–36 岁：身体下降加快，意识和心理仍可维持或增长。

替补席本身不产生高成长。持续首发、合理训练和健康状态可以让中游球队成为比豪门替补更好的发展路径。

伤病由负荷、体能、身体能力、年龄和随机状态决定。严重伤病可能降低潜力、造成长期属性修正或触发恢复事件。

## 8. 合同、租借与转会

报价由球队位置需求、球员 OVR、年龄、声望、状态、当前合同、球队财政和赛事级别生成。

玩家可以续约、拒绝续约、接受报价、要求经纪人寻找下家或留队等待。在适合的年轻阶段，球队可以提出租借。

合同至少包含期限、工资、预计角色和奖金。预计角色影响教练信任和出场概率；球队长期不履行角色承诺会提高转会事件权重。

## 9. 原创事件系统

MVP 至少内置 72 个原创规则事件，分为训练、伤病恢复、教练、队友、媒体、家庭、经纪人、国家队、合同和里程碑十类。

每个事件定义：

- 稳定 ID、类别和原创文案。
- 年龄、位置、状态、合同、国家队或历史标签等触发条件。
- 冷却期、互斥标签和每段生涯最大触发次数。
- 两个或三个玩家选项及其确定性效果规则。

事件可以改变能力、体能、士气、信任、声望、身价、伤病风险、合同状态、标签或未来事件权重。首版不调用 AI，也不要求网络连接。

## 10. GOAT Score

退役时生成 0–1000 分及分项说明：

| 分项 | 权重 |
|---|---:|
| 场上表现 | 35% |
| 团队奖杯与实际贡献 | 15% |
| 个人奖项 | 15% |
| 国家队表现 | 10% |
| 巅峰 OVR | 10% |
| 高水平生涯长度 | 10% |
| 影响力与关键里程碑 | 5% |

门将重点使用扑救、零封、失球控制、出场和评分；后卫重点使用防守贡献、零封、出场和评分；中场重点使用评分、助攻、组织贡献和出场；前锋重点使用进球、助攻、效率和评分。

表现按位置、赛事强度、联赛级别、难度和分钟数归一化。奖杯分数乘以玩家在该赛事中的分钟与表现贡献，替补奖牌不能等同于核心主力冠军。

退役页面必须展示总分、七项分数、主要加分来源及影响评分的生涯事实。

## 11. 页面范围

前端仅实现清晰可用的最小界面，不复刻任何目标产品视觉。

- `/`：三个存档槽、新建、继续、删除、导入和导出。
- `/career/new`：身份、位置、难度、seed、起始球队和初始模式。
- `/career/[slot]`：概况、下一步操作、状态、合同、赛程、积分榜和历史。
- 经典模式界面：训练/倾向、事件、赛季总结和转会。
- 详细模式界面：赛前、文字时间线、关键时刻和赛后报告。
- `/career/[slot]/archive`：逐季数据、转会、奖杯、奖项和国家队记录。
- `/career/[slot]/retirement`：GOAT Score、分项解释和生涯摘要。
- `/world`：查看、导入、导出或恢复默认世界。

页面使用原生表单、按钮、表格和少量基础 CSS，确保桌面与手机均可操作。不制作品牌视觉、动画或美术资源。

## 11.1 前端视觉基调调研（2026-08-27）

调研方式：实地截图同类产品的真实界面，涵盖三类代表性风格。结论用于确定 MVP 的视觉基调，不涉及逐像素复刻。

| 产品 | 风格类型 | 主色 | 布局特点 | 对我们不适用的部分 |
| --- | --- | --- | --- | --- |
| Il Nuovo Goat（复刻对象） | 深色电竞风 | 近黑底 + 黄/绿/红模式卡 | 大号品牌标题，居中单列，卡片化入口，营销感强 | 我们 MVP 不做品牌 hero 与美术；「一种模式一种强调色」的思路可借鉴 |
| Basketball GM / ZenGM 系 | 浅色工具风（Bootstrap） | 白底 + 单一主蓝色 | 顶部导航 + 左侧菜单 + 表格密集内容，信息密度极高 | 功能分区思路适用，但整体偏后台工具，缺少生涯叙事的情绪感 |
| Football Manager 官网 | 营销风 | 大图片 + 品牌色按钮 | 全屏视觉、营销文案驱动 | 完全不适合，我们是应用不是落地页 |

调研结论与选型：

- 产品是「生涯叙事 + 高密度数据面板」的混合体：既需要大量表格（积分榜、赛程、统计、转会记录），又需要生涯模拟器特有的故事时间线情绪。
- 采用**深色数据面板风**：近黑/深蓝灰底色（如 `#12151c`），文字高对比，数据表格为绝对主角；用克制的草绿系强调色标记「进行中/积极」状态，琥珀色标记「关键时刻/警告」，红色仅用于伤病与危险。避免 Il Nuovo Goat 多色卡片并存的电竞感，也避免 Basketball GM 的纯白后台感。
- 生涯叙事部分（事件、关键时刻、退役回顾）使用居中单列 + 大字号正文，与数据区形成节奏对比；数据部分使用紧凑表格与等宽数字（tabular-nums）。
- 字体：系统字体栈，正文 15-16px，表格 13-14px。
- 该基调落地为极简 CSS，不引入组件库，不做主题切换。
- 首屏即存档槽与「开始生涯」操作，不做营销 hero。

## 12. 错误处理与恢复

- 每次关键操作生成新状态后，先成功写入 IndexedDB，再更新界面中的已提交状态。
- 每个存档保留上一次成功操作前的恢复快照。
- 写入失败不得推进已提交状态，并向用户提供重试或导出当前内存状态的选项。
- 无效引擎状态返回结构化错误，不静默修复或生成半完成赛季。
- 不支持的版本、重复 ID、缺失球队、非法数值和损坏 JSON 必须显示具体字段路径。
- 首版只保证程序自身导出的未修改存档可重新导入；手工修改后的存档不承诺兼容。

## 13. 测试与验收

### 13.1 单元测试

覆盖随机数、赛程、比赛、成长、伤病、转会、事件触发、导入校验和 GOAT Score。

### 13.2 确定性测试

相同规则版本、世界、seed 和玩家指令序列必须产生完全相同的状态摘要与最终分数。

### 13.3 不变量测试

- 每场比赛积分分配合法，联赛积分来源可追踪。
- 每级始终有 10 队，升降级数量对称。
- 杯赛每轮晋级数量合法，淘汰赛最终必有冠军。
- 球员年龄、合同、伤病、数据和球队归属合法。
- 统计汇总等于逐场或逐赛事记录之和。

### 13.4 完整生涯测试

- 经典模式可从 16 岁运行到 36 岁并生成退役结果。
- 详细模式可通过自动选择测试策略运行到退役，且人工流程可以在关键时刻暂停和恢复。
- 两种模式均能在赛季边界切换并继续完成生涯。

### 13.5 浏览器端到端测试

覆盖新建、自动保存、刷新恢复、赛季边界切换模式、导出、删除、重新导入、世界导入失败保护和退役结算。

## 14. 非目标

MVP 明确不实现：

- 账号、云存档和服务端数据库。
- 世界排行榜、在线大厅、2v2、排位和聊天。
- 付费、广告、订阅或虚拟货币。
- 真实球队、球员、联赛、徽章或赛事名称。
- AI 生成文案或依赖外部模型 API 的功能。
- 完整 NPC 阵容和逐名球员转会市场。
- 目标网站的视觉、文案、素材或前端实现。
- 动画比赛、3D、音频或复杂视觉设计。

## 15. 交付物

- 可本地运行和构建的 Next.js 应用。
- 独立、可测试的纯 TypeScript 模拟引擎。
- 80 支原创球队及 4 国 8 联赛的默认世界。
- 至少 72 个原创职业事件。
- 三档 IndexedDB 存档和两类 JSON 导入导出。
- 经典与详细模式的完整可玩流程。
- 自动化单元、确定性、不变量和浏览器端到端测试。
- 世界数据库格式说明和本地运行说明。
